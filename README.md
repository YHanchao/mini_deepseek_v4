## Features / 项目亮点

- **零框架依赖 / Zero Frameworks** — 纯 PyTorch 手写，没有使用 HuggingFace Transformers、DeepSpeed、FSDP 等任何训练框架。Everything is hand-written in pure PyTorch.
- **Roast 吐槽数据集 / Custom Roast Dataset** — 22 个生活场景类别，约 2 万条吐槽段子，LLM 生成 + "喜剧编辑"筛选。A synthetic roast/humor dataset covering 22 life-scenario categories, generated by LLM and curated by a "comedy editor" agent.
- **完整复现 DeepSeek-V4 核心技术栈** — DSMoE (HashGate + Sqrt(Softplus) Gate)、Manifold Hyper Connections (mHC)、KV Compressor、Lightning Indexer、Multi-Token Prediction (MTP)
- **BPE Tokenizer** — 从零训练的 32K 词表 BPE 分词器。Trained from scratch.
- **优化器** — Muon + AdamW 混合优化器，带参数分组。Muon optimizer with Newton-Schulz iterations for matrix parameters.

## Architecture / 架构

基于 DeepSeek-V4 技术报告实现的核心组件：

Based on the DeepSeek-V4 technical report, the following core components are implemented:

- **DSMoE** — 前几层用 `HashGate` 做确定性路由防止坍塌，后续层用 `Sqrt(Softplus) Gate` + learnable bias 做负载均衡。Early layers use deterministic hash-based routing to prevent collapse; later layers use Sqrt(Softplus) gate with learnable bias for load-balanced expert selection.
- **Manifold Hyper Connections (mHC)** — 多流残差连接，通过 Sinkhorn-Knopp 迭代生成双重随机矩阵混合各流特征。Multi-stream residual connections with doubly-stochastic mixing via Sinkhorn-Knopp iterations.
- **KV Compressor** — 按 ratio 压缩 KV cache，支持重叠压缩 (ratio=4，滑动窗口) 和非重叠压缩 (ratio=128，均值池化)。Reduces KV cache memory with configurable compression ratios and overlap modes.
- **Lightning Indexer** — 可学习的稀疏注意力索引，通过 KL loss 独立训练，使模型学会关注关键 token 块。Learnable sparse attention indexer, trained separately via KL divergence loss.
- **Multi-Token Prediction (MTP)** — 额外预测头同时预测多个未来 token，加速训练收敛。Extra prediction heads for multi-token prediction to accelerate convergence.

详见 [src/deepseek.py](src/deepseek.py)。

## Post-training: Roast / 后训练：学会吐槽

### Data Synthesis / 数据合成

受限于 0.3B 的模型容量，常规的数学/代码任务难以胜任。于是选择了让模型学会吐槽作为后训练任务，构造了 Roast 数据集，由 DeepSeek-V4-Flash 生成。

Given the model's limited capacity, standard math/code reasoning was impractical. I chose to teach the model to generate roast/humor responses instead. The Roast dataset was synthesized via DeepSeek-V4-Flash.

**Pipeline**：22 个生活场景类别 (职场、科技、社交、饮食等) → 生成约 2.3 万个具体吐槽主题 → 喜剧提示词为每个主题生成 4 条候选段子 → "喜剧编辑" LLM 从 4 条中精选最佳 → 约 2 万条最终数据。每条包含原始主题、4 条候选段子和编辑评分（观察力、笑点、原创性、简洁性、整体）。

The data synthesis involves a "writers' room" pipeline: 22 life-scenario categories → ~23k concrete roast topics → 4 candidate responses per topic → a "comedy editor" LLM selects the best one. All responses are written in observational stand-up comedy style, 30-50 words each. The final dataset contains ~20k examples with full scoring metadata.

### Training Approach / 训练方案

尝试了 DPO、GRPO、SimPO 等多种偏好对齐方法，但受限于 0.3B 的模型尺寸，模型始终无法正确对齐偏好（4 条 response 的 top-1 准确率约 22%，pairwise 比较准确率约 46%）。

最终选择 **WeightedSFT**：利用已有的评分数据，对高质量 response 给予更高权重。

Multiple preference alignment methods (DPO, GRPO, SimPO) were attempted but the model couldn't reliably distinguish good from bad roasts. WeightedSFT was the pragmatic solution, using editor scores as sample weights:

$$
\mathcal L = g^{-1}\sum_{g=1}^G \sum_{i=1}^4 w_{gi} \ell(\pi(X_g), Y_{gi})
$$

- **Winner** (最高分 response) 权重始终为 1.0 / The best response always gets weight 1.0
- **Loser** 权重由 `weighted_min` 控制，通过 reward 线性映射到 `[weighted_min, 1]`
- 初期 `weighted_min = 0.7`（优先学到吐槽风格分布），后期余弦衰减至 `0.2`（类似 rejection sampling 调整分布）
